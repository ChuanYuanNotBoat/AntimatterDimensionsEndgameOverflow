# Localization and ADEChinese synchronization

Every language is maintained in **one file**: `src/locales/en.json`, `src/locales/zh-CN.json`, etc. The build discovers these files automatically. A new language requires no component edits or import-list changes. Copy the English file, change `$meta.id` to match the filename and set `nativeName` and `direction` (`ltr` or `rtl`). Delete untranslated entries: the game falls back to the complete English message.

## Shared terminology

Translate each complete resource name once, under its semantic `terms.*` key. Sentences reference that key:

```json
{
  "terms.celestialInfinityPoint": "天界无限点数",
  "prestige.example": "获得 {amount} [[terms.celestialInfinityPoint]]"
}
```

References are expanded before ICU compilation; changing the term updates every referring message. Chinese normally needs just one string. Languages requiring grammatical variants can provide an object with a required `text` form and optional named forms:

```json
{
  "terms.celestialInfinityPoint": {
    "text": "Celestial Infinity Point",
    "plural": "Celestial Infinity Points"
  },
  "prestige.example": "Gain {amount} [[terms.celestialInfinityPoint|plural]]"
}
```

When a translated term omits a requested form, its `text` is used. An omitted term inherits the entire English term. Unknown references, reference cycles, invalid ICU, and malformed replacement packs are rejected atomically. Existing valid packs remain active. Keep resource entries independent and translate their **whole names**; do not construct Celestial Infinity Points from translations of Celestial, Infinity, and Points.

The importer matches the longest complete resource name first. At runtime, generic display patterns cannot capture a fragment of a known multiword resource. Matching metadata in `src/i18n/*-rules.json` and `display-terms.json` contains IDs, forms and scopes only; English matching text is read from `en.json`. No Chinese display translations belong in components, model configuration, import scripts, or matching metadata.

## Translation coverage and source

Text is imported from [mushduck/ADEChinese, exp](https://github.com/mushduck/ADEChinese/tree/exp), revision `27fc05ba8c57aa1f476b3bc156b7895ad0568943`. It is aligned against this fork's English source and the reference project's English predecessor `796a911c74a8e55e345e2e15480f31ed5b590237`. Both projects retain their MIT notices. Only text is reused; reference game logic and cheat controls are not copied.

The import includes matching component labels, dynamic descriptions, prestige/header text, dimensions, automation, achievements, challenges, options, help, news and celestial quotes. `docs/adechinese-sync.json` records source revisions, per-key locations, and unmatched definitions. Generated `ade.*` keys remain stable during community editing; semantic `terms.*`, `options.*`, etc. keys identify reusable concepts. Missing or ambiguous matches and version-specific content remain English. Catalog coverage is **not** a claim that every game state is fully translated.

To update the reference import, use unlocalized English checkouts:

```sh
node scripts/sync-adechinese.cjs /path/to/ADEChinese \
  --source /path/to/current-English-source \
  --extra-source /path/to/reference-English-predecessor
```

Existing catalog entries are preserved, including community corrections. New entries are added to the two language files and shared terms are referenced automatically. Run the checks below and review the resulting diff. `--migrate` is for the initial template conversion only; it is blocked once templates are migrated to prevent overwriting manual changes. Normal translation updates never need this option.

## Display and identity boundaries

- New UI uses `$t(key, values)` or `textRef(key, values)`. Preformat Decimal values with existing format helpers. Never coerce game quantities into native numbers for translation.
- Saved names, keys, IDs, Automator grammar, lookup strings, styles, input values and user-defined names stay canonical. Localization happens only when rendering output. Audit producers and consumers before changing a display-name producer.
- The legacy display adapter matches complete rendered English strings, resolves ambiguous translations by component scope and preserves unmatched text. It never rewrites the game model or arbitrary words in a sentence.
- `LocalizedText` reorders original styled VNodes through named slots. Conditional chains stay together in one slot. Language packs supply text, never executable HTML. Legacy trusted game HTML is parsed inertly and translated via `textContent`; links, classes, scripts and code blocks are preserved.
- Locale preference is application-level `ade.language`, outside `player`. Switching language refreshes paused views and cached descriptions without advancing time, changing the save, restarting the news ticker or consuming resources.

## Validation

```sh
npm run i18n:check
npm run i18n:audit
npm run test:i18n
node --test tests/ethereal-sector-number-boundary.test.cjs
npm run build:release
```

`i18n:check` validates one-file metadata, duplicate keys (including forms), references, ICU syntax, parameters/selectors, display IDs, rich-text IDs and migrated template text. The identity audit locates suspicious string indexes and dispatch; it does not change them automatically.

2026-10-03 validation: 31 i18n/domain tests and 11 Ethereal-sector tests pass. Full suite: 420 tests, 372 pass, 48 fail; the failed test-name set equals the baseline. A separate comparison of 435 migrated Vue components confirms that control attributes, input bindings, keys, classes, styles and event handlers remain unchanged. Scripts remain unchanged except the reviewed help-search and news-display adapters. Production-page checks cover both layouts, late header/currencies, dimensions, automation, options, achievements, upgrades, glyphs, Chinese help search, English restoration and unchanged serialized player data.

Keep `intl-messageformat` in `transpileDependencies`: this project's Webpack 5.64 cannot correctly handle its original class static-block import references. Verify the real built page, not only the build exit status.
